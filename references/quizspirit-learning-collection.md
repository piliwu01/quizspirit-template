# QuizSpirit 學習進度與圖鑑收藏擴充

當使用者要求錯題本、進度保存、句型／單元掌握度或收集稱號時使用。可選元件位於 [../assets/quizspirit-learning-pack/](../assets/quizspirit-learning-pack/)，不依賴舊聊天資料夾；基礎範本維持原玩法，只有換題庫的工作不自動加入所有擴充。

## 套件與整合

將套件的 `src/` 模組與 `scripts/` 測試複製到遊戲副本，不覆蓋既有 App 或 question-bank.js。元件使用 React 和隨附 CSS，沒有新增依賴。沿用專案已存在的 storage、題庫與角色來源，不硬寫課程名稱或公開網址。

- `learning.js`：讀取有版本的本機進度、逐題紀錄及單元統計。套件提供的 key 是示例；新遊戲選擇獨立且穩定的 key，既有遊戲保持相容或明確遷移。
- `LearningPanel.jsx`：傳入 `bank`、`records`、`onAnswer(key, correct)`、`saveNotice`；題目使用標準題庫契約，紀錄 key 為 `bankId:questionId`。
- `collection-titles.js` 與 `CollectionTitles.jsx`：傳入 `captured`、`catalog`；`compact` 用於首頁，完整清單用於圖鑑頁。稱號由已保存的收藏推算，不另存一份可能失去同步的稱號狀態。

在 App 初始化時只讀一次存檔，恢復 `records`、玩家夥伴、`captured` 與連勝；以 effect 在資料改變時保存。保持原題庫 ID 和學生既有進度。載入需檢查版本、資料型別、題目紀錄與題靈 ID；儲存失敗在畫面顯示「僅本次有效」。壞 JSON 回退安全初始值；別在每次 render 重置資料。這套本機保存不是登入或跨裝置同步。

戰鬥答對、答錯與逾時都呼叫同一個紀錄入口；每題使用同步 ref 鎖，防止連點或逾時和點擊同時結算。新題才釋放鎖。沒有題庫 ID 的自動算術不寫入課程統計。對戰中途刷新可選擇重開新戰鬥，需在 UI 說明；不要把夥伴／收藏保存宣稱為 HP、動畫及回合都可恢復。

## 錯題與掌握度的意義

- 首次答對率＝不同題目第一次答對數／已練習的不同題數；未作答顯示尚未作答，不當成 0% 能力。
- 目前已掌握＝最近一次答對的不同題目數；分母為該題庫或單元的 active 題數，提供覆蓋範圍。
- 答錯／逾時加入待複習；錯題重練不限時、顯示答案解析，重答正確移出待複習。再次答錯重新加入；保留首次成績與錯誤歷史。
- 每輪錯題清單採開始時快照，逐題完成，避免答對移除後索引跳題；空錯題本顯示空態並停用開始按鈕。切換題庫重設複習 UI，各題庫統計分開。

## 圖鑑收集稱號

分母必須是當前遊戲實際可收服的角色池，不能拿名冊以外的角色當目標。依角色 ID 去重，初始角色是否計入先說明。搜尋或選擇出戰角色不等於收服；未知角色與重複紀錄不增加收集度。門檻由 `ceil(總種數 × 百分比 / 100)` 算出，解鎖判斷使用種數，避免顯示百分比四捨五入而提前解鎖。

本次可用的範例（可依新專案調整）：新手冒險者 0%、森林探索者 10%、圖鑑收藏家 25%、夥伴召集人 50%、聯盟收藏大師 75%、全圖鑑傳說 100%。64 種池對應 7、16、32、48、64 種。首頁顯示目前稱號、已收集／總數、距下一階差幾種；圖鑑顯示所有稱號與解鎖狀態，滿圖鑑顯示完成訊息。純收藏稱號不改 HP、傷害、收服率。

## 驗證與交付

在套件根目錄或整合後專案執行：

```text
node scripts/learning.test.mjs
node scripts/collection-titles.test.mjs
```

這些是邏輯檢查，仍需實際 UI 測試：答錯 → 刷新仍在 → 錯題答對移出且掌握度增加 → 首次結果不變；夥伴變更與收藏跨刷新保留。稱號測試每個門檻前後、去重、滿圖鑑、未知 ID、既有存檔。用隔離測試資料，避免在學生正式紀錄中灌入假收藏；無法隔離時說明哪些只驗證純函式。

桌面及實際 innerWidth 390 px 等代表尺寸檢查：長題幹、單欄選項、解析、稱號清單、儲存提示無裁切，scrollWidth 不超過視口。截圖肉眼核對，完畢恢復原視口。更新首頁文案與頁尾，移除「重新整理重設收藏」等已過期說明；同步更新獨立 HTML、題庫、可修改來源與正式網站。公開版本依 [發布核對](qa-release-manual.md) 驗證。
