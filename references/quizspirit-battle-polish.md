# 題靈冒險：戰鬥演出與規則深化（2026-11-21～22 案例）

國文全班討伐線上版（React＋Cloudflare Worker／D1／Durable Objects）實作紀錄。數值限本案；新專案先確認玩法再挑選。靈感可參考 JRPG 的破盾、蓄力等通用機制，但名稱、角色、畫面一律原創（本案用《山海經》神獸），不仿製特定遊戲的外觀。

## 使用者的工作節奏

- 老師提需求（常附截圖）→ 先回答「目前做到了嗎」並說明差距 → 用 wrap_up 問「要做嗎」→ 做完在本機實測三種尺寸 → 問部署 →「部署並推上」才部署＋commit＋push。
- 新玩法先給「規則草案＋互動試玩草案」（show_widget），使用者選定版本（例如「弱點先翻開 1 個」）再做。
- 每次功能改動在 README.txt 末尾補一段（含日期）。部署後 curl 正式站：首頁 200、新 JS／CSS 含新字串。

## 個人對戰

- **破盾與蓄力**：敵人 2 種弱點題型、4 點護盾；答對弱點題型 −1，歸零破盾（下一題 ×2、答錯不反擊，之後回滿）。靈氣開場 1、答對 +1、最多 5；出招前投入 0～3（×1.5／2／2.5），不論對錯都用掉。招式卡快攻／強攻／必殺＝易／中／難，每張標題型，至少 1 張弱點。只用題庫中 ≥10 題的題型（`weaknessPool`）。
  - `/answer` 不帶題庫，所以開戰時把題型清單存進 `battle.cats`，換牌不必再讀題庫。
- **隱藏弱點**：開戰只翻開 1 個（`battle.revealed`），答對另一題型才翻開。`publicState` 把未翻開的換成 `null`（畫面顯示「？？」），不把答案傳到學生裝置；舊對戰缺 `revealed` 時全部公開。
- **潛力爆發**：被反擊扣血 +35、破盾 +50，滿 100 可按「覺醒」：該題 ×3、答錯不反擊、不用靈氣，發動即歸零；收服不能覺醒。
- **演出**：破盾／覺醒斜長條切入特寫（3 秒，減少動態 1.5 秒）；勝利結算數字跳動（答對、XP、最高連擊、破盾、食物、玉符、寶箱）。
- **狀態圖示**：對手（破盾 1 題、灼燒 N 回、暴走、虛弱）、夥伴（覺醒、蓄力、玄甲 N 次、連擊 N）。綠框有利、紅框警示，title 說明。
- **蓄力＝多段攻擊（2026-11-24，只限單人冒險）**：投入 N 點靈氣＝打 1+N 下；答對弱點題型時護盾扣 `min(剩餘, 1+N)` 格（`resolveBreak` 回傳 `hits`），投入 3 點可一次破盾；倍率 ×1.5／2／2.5 不變，答錯或非弱點不扣盾。提示文字「2 連擊 ×1.5」，戰鬥紀錄「弱點 3 連擊！護盾 −3」。討伐、PVP 不動。
  - 演出：夥伴腳下光環（1 藍、2 紫、3 金＋旋轉圈、覺醒粉紅，`boost-aura boost-N`）；命中 N 個衝擊環錯開＋「N 連擊！」；護盾格逐格 `shatter`（用 useRef 記上一次護盾數）；投入 3 點答對且沒破盾才播金色「靈氣全開！」特寫（破盾／覺醒優先用原特寫）；減少動態全部關閉。
  - 來源：老師貼遊戲影片問「哪些能融入」→ 先列 4 個點子（含規則與成本），老師回「做 1 和 4」才動手。

## 共同討伐

- **學生頂端固定戰況條**（sticky）：魔王頭像、血條、我的傷害、我的修復；數字增加時跳動，暴走時頭像紅框。原本的魔王 HP 格移除避免重複。
- **答題區 8：2**：電腦／平板題目 80%、技能區 20%；手機上下排列。
- **魔王登場標題卡**（投影，開戰 2.5 秒內才播，重新整理不補播）與**技能斜長條**（預告瞬間橫掃，投影與學生都有）。hide timer 放在獨立 effect，否則 cleanup 會取消計時、畫面卡住。
- **全班共用魔王護盾**：點數＝人數（4～30），2 種破盾題型（先翻開 1 個）。任何人答對破盾題型 −1；墨甲護體期間不扣。歸零破盾 10 秒全班 ×2，之後回滿並換題型（新題型也只翻開 1 個，恢復訊息不可洩漏隱藏題型）。**Durable Object 的 alarm 計畫必須加入 `bossShield.until`**，否則要等下一次有人作答才恢復。暫停時順延。
- **行動順序列**：60 秒時間軸（魔王反擊、出招預告／發動、技能結束、破盾結束、合體技冷卻、時間到），相近事件上下錯開，標籤單行「魔王反擊 27 秒」以節省高度。投影版放在戰況列下方，注意投影全螢幕時會壓縮戰場高度。
- **狀態圖示**：魔王頭上（暴走、技能剩秒、暈眩、破盾、毒傷），「我們的隊伍」旁（守護 N 波、戰鼓 N 秒），學生畫面排成一行。魔王嘲諷泡泡會短暫重疊，圖示 z-index 放上面。
- **結束後**：
  - 剩餘時間定格：結束時存 `leftMs`（暫停中結束以暫停時刻計），前端不再用時鐘倒數。
  - 一鍵加入下一場：`GET /raid/<舊碼>/after` 找同老師、同班、之後建立且仍進行中的房間；學生結算頁每 4 秒查一次，出現金框發光、「👇 按這裡加入」、整排大按鈕，並自動捲到提示。不沿用舊房間碼（成績與獎勵會混在一起）。
  - 強制把學生從其他頁面帶進討伐：需要輪詢，Cloudflare 免費方案每日請求有上限；使用者決定不做，改請學生停在討伐頁。
  - 全班戰績榜：依貢獻（傷害＋修復）排序，稱號 Lv1～Lv9 依與最高者的比例，標籤（最後一擊、傷害第一、守護第一、全對、連擊王、破盾 ×N），易／中／難答對數，摘要列（用時、限時、攻擊、合體大招、破盾、魔王反擊、剩血）。**老師看全班、學生只看自己那列**（原設計不顯示倒數排名）。投影按鈕：嵌入式瀏覽器的 requestFullscreen 可能被擋，失敗時改成 fixed 蓋滿視窗（Esc 關閉）。

## 防背答案：每次打亂選項

- 在伺服器建立題目時打亂（個人對戰 `questionFor`、討伐、PVP 抽題、試煉與墨漬怪都經過同一處），判分用打亂後的答案。
- 解析字母同步：`(A)`、`選項B`、`B選項`、`故選C`、`答案是D` 一次替換（避免 A→B→C 連鎖）；逐項「(A)…(D)…」解析依新字母重排，句尾句號留在最後。
- 選項互相參照（以上皆是、(A)(B)皆對、A與B…）不打亂；數學題不動。
- AI 小老師的說明快取用原字母，前端帶 `order`，伺服器回傳前換成畫面字母。
- 舊測試若寫死 `choice:'A'` 會壞：改成依選項文字找正確鍵，或用伺服器內部的 `pending.answer`。

## 版面與驗證經驗

- 三種尺寸 1920×1080、1366×768、390×844 都用 `getBoundingClientRect` 量：元素是否超出卡片、是否被戰場（overflow hidden）切掉、是否互相重疊、是否橫向捲動。截圖可能拍到淡入動畫的第一格，以量測為準。
- 個人對戰在「一起看解答」出現時戰場最矮（筆電約 260px）：夥伴卡片要精簡（矮螢幕隱藏副標、上移），新元素放進既有一行而不是新增一行；手機卡片放不下時改放到行動區（例如潛力條移到「你的回合」下方、狀態圖示移到戰場左上兩行）。
- CSS 分散在多個檔案時，後載入的舊規則可能蓋過新規則（如 `.raid-student-grid` 欄寬、`body.battle-focus .boost-pick{flex-wrap:nowrap}`）：用重複 class 或更具體的選擇器提高優先順序。
- 模擬多人：node 腳本用臨時 `zztest-` 帳號建房、加入、作答（可讀本機題庫 JSON 取得正解）；前端驅動作答可用「題幹雜湊→答案」小表放 localStorage，測完刪除。不要把測試檔放進會發布的 `public/`。
- 每次 build 後重啟本機預覽伺服器；模擬視窗大小改變後若版面數字怪異，重新整理再量。
- 測試帳號建立與清理依 production-verification.md 的順序，結束回報剩餘 0 個；正式站只做 curl 檢查，不在真實學生帳號上測。

## 右側瀏覽器面板卡住時的本機實測（2026-11-25）

- 症狀：面板隱藏或 navigate 逾時 300 秒、javascript_tool 回「page still loading／Policy check temporarily unavailable」，開新分頁也一樣。先請老師把面板打開；仍卡就改用無頭 Chrome，不要一直重試。
- Playwright：用 npx 快取裡現成的套件（`createRequire` 指到 `npm-cache/_npx/<hash>/node_modules/`），`chromium.launch({channel:'chrome'})` 用系統 Chrome（快取的 Playwright 瀏覽器版本常對不上）。不另外下載。
- 開著 `wrangler dev` 時，`wrangler d1 execute --local` 會失敗（Failed to get session commit token）：改用 Node 內建 `node:sqlite` 直接開 `.wrangler/state/v3/d1/miniflare-D1DatabaseObject/<hash>.sqlite`，`new DatabaseSync(path,{timeout:10000})` 避免 database is locked。
- 造情境：`/battle/start` 每次都新開一場，重新整理也不會接續 → 開戰後再改資料庫（orbs=3、`revealed=weak`、cards 題型全設成弱點、hp 拉回 500 免得打死）。前端的靈氣數只在下一次作答回傳時更新，所以先「投入 0 答一題」當引子，再改 cards、投入 N 點測。正解從資料庫 `pending.answer` 對 `pending.options` 找索引。
- 冒險奇遇會隨機跳出擋住點擊：`page.addLocatorHandler(page.locator('.encounter-overlay'), …)` 自動按「略過」。
- 390 寬量到戰場內元素 x 為負：是 Playwright `click()` 先 scrollIntoView，把 overflow:hidden 的戰場（背景 SVG 本來就比戰場寬）捲動了；改用 `page.mouse.click(座標)` 模擬手指就正常。回報時說清楚是測試工具造成、不是版面問題。
- 特效用每 150ms 輪詢記下「出現過的最大值」（衝擊環數、連擊字樣、碎裂格數、特寫 class），比截圖可靠。
