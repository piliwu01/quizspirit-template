# 老師投影戰場與學生答題畫面

適用既有 QuizSpirit 討伐的雙畫面改版，或使用者要求「每個人出招都在螢幕看到」「全班角色一直留在戰場」。來源為 2026-11-10 本機 4.1.0。先核對專案程式與使用者確認範圍；單純換題庫時不加入此改版。

## 已確認的呈現分工

- 老師投影：魔王在左，全班出戰角色在右側常駐。依加入順序固定位置，不因排行榜重排；顯示學生姓名，等待中換角仍按原規則，開戰後鎖定。支援 1–60 人，超過 36 人精簡次要角色名稱，保留學生姓名。角色尺寸須同時依實際戰場寬度、高度、行列數計算，不能只依螢幕寬度放大。
- 學生裝置：保留精簡魔王 HP、共用護盾與倒數，以題目、選項、解析、技能及背包為主；全班隊伍收進可展開區域，不載入全班大型戰場，也不等待動畫才准答題。本案沿用「解析後按下一題」，不得把視覺改版誤寫成已實作自動跳題。
- 答對角色前進／發光、攻擊命中魔王，顯示姓名與實際傷害；技能、修盾、各道具與魔王反擊有不同效果。多人同時播放，不排隊累積幾十秒延遲。數值由服務端決定，畫面不另外扣血、扣道具或發獎。
- 沿用既有 PNG 做整張圖位移、跳躍與特效，不宣稱逐格揮手／轉身；使用者曾取消的配件疊圖換裝與提示卡不重新加入。參考遊戲截圖只用於佈局討論，不表示已有其動畫素材。

## 同步與重連

保留房間 createdAt＋code 身分及單調事件 sequence，先接收快照再依序號整理出招。首次載入建立游標，不重播歷史；相同／較舊快照不重播。房間切換清空舊效果；近期未見事件可補播，本案以 serverNow 與事件 at 判斷最近 5 秒，避免重連後補播整場。

本案服務端持久事件緩衝由 24 增至 256，以容納全班出招與道具事件；老師可收到完整緩衝，學生只收最近 24 筆，避免讓所有手機接收投影資料量。一次 React 更新可能合併多份快照，因此不能只用 events[0] 表示所有人攻擊。勝利最後一擊也須播放，不能只在 active 狀態讀取新事件。

256 筆是有限緩衝，不保證任意流量或長時間斷線都不漏動畫。驗收須記錄發送事件數、速率及預期的 sequence／actorId 集合，逐筆比對，不只看不同 actorId 總數；本案 60 人測試是單輪每人 1 次答對。若保留的最舊事件序號大於游標加 1，表示可能已截斷，應記錄缺口；不能補造傷害或假裝所有招式已呈現。本版沒有永久事件補拉，超過緩衝或 5 秒補播視窗時以最新正式戰況為準；若新需求要求逐筆永久送達，另設可持久補拉的事件機制並測試。

暫停需同時凍結效果生命週期與 CSS 動畫；剛收到出招就暫停時，姓名傷害仍須可見，避免動畫停在 opacity:0。恢復後繼續清除已到期效果；卸載清除 timer／observer。減少動態設定改用靜態姓名、數字與效果，不單靠顏色區分。

## 滿版與樣式

優先 requestFullscreen；拒絕時使用視窗內固定定位滿版。切換按鈕、原生 fullscreenchange、Esc 都要同步介面狀態；退出／卸載恢復原本文件捲動。滿版仍保留老師暫停及結束控制。原生全螢幕與視窗滿版備援分別記錄驗證，不能只測備援就宣稱原生已通過。

新增樣式先比對舊站 class 名稱。本案 arena-caption 與舊樣式衝突，改為 raid-stage-caption；不要用覆蓋全站通用樣式的方式修正。實際檢查 30／60 人角色框、姓名行距、戰場邊界及底部資訊列，並檢查 390 × 844 學生畫面無水平溢出。

## 可攜來源與檔案地圖

新檔 src/RaidStage.jsx、src/raid-stage.js、src/raid-stage.css；接入 src/RaidApp.jsx；shared/raid-rules.js 管事件緩衝，server/raid-room.js 區分老師／學生事件資料量。scripts/raid-stage.test.mjs 與 raid-backend.test.mjs 覆蓋核心與整合；npm test 包含兩者。使用既有 create-quizspirit-online-project.mjs 複製乾淨多人範本，不覆寫既有遊戲或玩家資料。

## 驗證順序與已知界線

1. 規則／資料：首次不重播、序號去重、換房、近期重連、最後一擊、60 人事件不遺失、實際傷害／修盾。確認老師不取得學生私有題目／答案。
2. 隔離登入實際出招：30／60 位不同學生，觀察老師 DOM 事件中的不同 actorId，而非只查 HP 總和；暫停後再次取樣確認效果不消失。重取快照不能重播。
3. UI：老師滿版、Esc、減少動態、實際魔王倒數反擊、各道具、學生手機按下一題與作答；排布不能只靠 build 或截圖推測，量測框是否重疊／超界。
4. 建置／交付：先備份、來源白名單打包，排除 work、.wrangler、node_modules junction、測試 SQL、帳密、cookie 與學生資料；重開 ZIP 比對 hash。

來源 4.1.0 曾通過 120 項自動測試與建置，實際瀏覽器觀察到 30／60 位不同學生的出招；30 人 HP 3,000→2,700，60 人 6,000→5,400；30／60 人角色框沒有重疊，60 人全在戰場內；390 × 844 學生頁可作答、修盾且無大型戰場或水平溢出。原生全螢幕在測試瀏覽器被拒，驗證的是視窗滿版備援。60 人為同一電腦隔離登入及 API 操作，只有老師與代表學生頁開啟，不是 60 台實機或 60 個同時 WebSocket 的負載測試。上述是有日期的案例證據，複製範本後仍須重測，不等於已公開部署。

若 Wrangler 靜態檔案 watcher 因權限失效，重新建置後須重啟本機服務、重新整理並核對 bundle；不要刪除玩家資料。改版不改傷害、魔王 HP、經濟、PVP 或資料庫規則；新案若要改規則另行確認。
