# 驗證、部署與操作手冊

## 測試矩陣

依變動範圍選擇測試，不要求每次文字修改重跑全部整站：

- 題庫：來源核對、結構、有效題數、排除題及答案不在公用 payload。
- 規則：首次／重複 XP、等級邊界、可達性、勝敗分母、技能保底、重答、錯題重新入池、抽卡機率及保底。
- 保存：跨帳號拒絕、同 request ID 重送、競態、舊進度、權限、未完成戰鬥恢復、401 最多重試 1 次。
- 視覺：角色 × 階段 × 造型檔案對應、圖片失敗、桌面、390 px 等代表手機尺寸、不覆蓋題目、減少動態。
- 聲音：初始靜音、volume-only 記憶、context／排程清理、真實播放、背景事件、試聽與去重。

用隔離 BrowserContext 進行獨立情境，避免之前的 init script、localStorage、登入狀態及媒體設定污染後續測試。圖片 lazy 載入可能讓畫面外的 decode 等待；測試頁可 eager 或逐張捲動，但不要為測試擅改正式圖片載入策略。等待設合理上限，卡住時查明是哪個步驟，不無限等。

本機展示模式可驗證 UI，但若戰鬥規則與正式後端不同，不能用展示成功宣稱正式帳號流程已測完。每一項證據註明是純函式、模擬事件、真實瀏覽器、正式資產或真實登入端到端測試。

## 發布到既有網站

### 網站角色卡片對齊

角色圖片使用 `height:auto` 時，不同原圖比例會讓名稱、技能及按鈕上下錯位。先核對圖片元素與卡片各區的實際尺寸，區分原圖透明留白、圖片容器高度與文字換行；不要只移動某一隻角色來掩蓋排版問題。

讓同一排卡片共用一致的圖片區高度，圖片採 `object-fit:contain` 並置中，保持原比例、不裁切。圖片、名稱、技能名稱、說明與操作按鈕分區；使用 grid 或等效布局保留說明空間，按鈕靠底部且不覆蓋文字。高度依現有角色、卡片寬度及斷點選擇，不將墨境討伐曾用的桌面 270 px／手機 240 px 固定成所有專案規格。若只是對齊修正，保留原圖片、名稱、技能、按鈕行為及玩家資料。

在隔離本機畫面測試實際共用元件，避免另外仿製卡片卻漏測正式結構。桌面量測同列卡片的圖片區、名稱、技能、說明及按鈕上緣是否對齊；容許合理的次像素誤差，例如 1 px。逐卡確認各區沒有重疊、按鈕留在卡片內、圖片完整載入且維持原比例。手機單欄改檢查區域順序、安全間距及無橫向溢出，不要求不同列的絕對座標相同；另測桌面放大文字，避免說明換行後按鈕再度錯位。

保存桌面與代表性手機尺寸的卡片截圖及量測報告，肉眼檢查圖片、名稱、技能與按鈕；檢查 TypeScript、lint 與 production build。不要為排版驗證在真實玩家帳號締結角色契約。正式更新另取得授權，不因本機修正完成就自動發布。

發布後核對原正式別名及 READY 狀態，確認正式載入的 CSS 含這次布局規則。CSS 壓縮可能將 `center` 改寫為等效的 `50%`，驗證應檢查等效效果，不因字串差異誤判部署失敗。正式樣式存在與本機卡片布局通過是不同證據，不能因此聲稱已操作正式登入帳號的選角流程。

### 正式部署核對

新部署或對外更新需要使用者授權。先確認專案與團隊 ownership、正式 domain 及環境變數；不要擅自新建同名專案或登入其他團隊。敏感值留在服務設定，不進輸出檔。

先跑相應測試、lint／typecheck／build，再部署。存錄 deployment ID、READY 狀態及正式別名；在正式網址核對資產 hash 或版號、關鍵 bundle／CSS 與必要的安全可行互動。READY 前不能宣稱已上線。

Vercel 出現 Not authorized，先檢查目前身份、scope 與 project linkage，再重試相同授權專案。有證據是版本相容性時才試已知成功版本；不把舊日期版本永久寫死成通用命令。反覆相同錯誤且沒有新證據時，停止外部變更並請使用者確認授權。不要把部署錯誤當理由清資料或改登入服務。

若只有匿名檢查正式資產，清楚說明完整戰鬥是在本機測試；不擅自變更玩家 XP、抽卡或帳密來證明功能。

## 手冊從實作產生

交付學生可閱讀的規則，不照抄初版提案或過期測試模式。核對至少以下項目：

1. 正式入口、版本、帳號操作與可保存進度。
2. 初始角色、技能機率／保底、重答保護。
3. 單元順序、每場題數、勝敗、連擊及中斷恢復。
4. XP／等級、首次判定、成長形態與可達性算例。
5. 解析、錯題、掌握及再次答錯。
6. 召喚券來源、抽卡公開機率、保底、墨晶兌換、換裝與預覽。
7. 聲音、動畫、手機操作與本機設定。
8. 常見錯誤、共用設備安全、未實作功能邊界。
9. 學生練習建議與教師使用提醒；建議不可寫成遊戲內已存在的任務或獎勵。

依使用者需要製作 PDF、Word 或 HTML／Markdown，保留可修改來源。PDF／Word 遵循對應技能，重新開啟、提取內容及逐頁渲染檢查，確認頁數、頁碼、表格、中文字、裁切與來源身份。字串抽取遇相容字形或換行時先正規化，不把抽取不完全直接當成視覺缺字。

## 學生手機懶人包

當使用者要把操作手冊做成學生手機圖卡，先從已實作且已核對的手冊濃縮內容，不從早期提案或記憶補寫規則。開始製作前確認張數、尺寸、視覺方向、配色、文字密度與是否放正式入口；若前文已完成選擇，就沿用，不重問。常用交付是 2 張 1080 × 1920 px 直式 PNG，但使用者指定其他尺寸時以其需求為準。

內容以「能立即開始」及「遊戲中最常查」分頁。第 1 張可放登入／註冊、初始角色、關卡入口、戰鬥數字與排行榜；第 2 張可放 XP、進化、錯題掌握、抽卡、貨幣與排錯。這只是常見資訊架構，不把範例中的角色、數值或頁數硬套到其他遊戲。所有 XP、HP、機率、保底、等級、密碼與重算時間都須回查當前實作或正式設定。

優先沿用專案內已確認的原創角色與透明 PNG，不重新生成近似角色。視覺風格與配色先讓使用者確認；學生手機閱讀以辨識度優先，繁體中文標題、正文、註解與頁尾預設採清楚的粗體中文字型，英文與數字同步加粗。小字使用足夠深的墨色與明顯對比，避免細字、淺灰字、過密段落和只在大圖上看得清楚的設計。若使用者反映字體不清晰，先統一加粗與加深文字，不擅自增加裝飾或改動已確認版面。

正式入口只能使用已確認網址。QR Code 不能只確認「已畫出來」：輸出後要從成品實際裁切並解碼，核對結果與正式網址完全一致。若正式網址尚未確認，保留清楚占位並標示未完成，不製作可能誤導學生的 QR Code。

### 題靈冒險說明卡改版（老師說「更新遊戲說明」）

- 說明卡是 8 張 1080×1920 圖（`public/guide/1~8.webp`，頁名在 `src/GuideViewer.jsx` 的 PAGES），由桌面 `claude-ai/generated/quizspirit_cards/build_cards_vN.py` 產生：插圖（不含字）＋HTML 排字＋無頭 Chrome 截圖；`measure_vN.py` 量內容底部（≤1820）、截斷與換行項目。
- 流程：從 README 找出上次做卡之後的新功能（例如健檢分頁、被動數值、同行夥伴、多段蓄力、奇遇、天賦、十連抽、寶箱全開、山海魔王），逐張列出「要補什麼」→ 複製成新版號腳本（舊版保留）→ 只改文字 → 量測超出就縮插圖高度 H（例如 640→510）或把兩行併一行 → 拼小圖總覽看一次 → PIL 轉 WebP（quality 88、確認尺寸 1080×1920）→ README 補一段。
- 插圖不用重畫、檢視器程式不動，只換同尺寸圖時不必開本機伺服器；部署後用 sha1 比對正式站 8 張圖。

### A4 滿版圖卡與角色卡片防遮擋

當手機圖卡改製為 A4 滿版講義，先確認直式／橫式、單面／雙面、滿版或留白，以及列印解析度；常用直式 A4 成品為 2480 × 3508 px、300 dpi，但以使用者指定規格為準。不要只把手機版等比例放大，應重新分配各區高度，確保教室列印與手機縮圖都能閱讀。

含角色、靈獸或技能的卡片，依「角色圖 → 名稱 → 技能色塊 → 技能說明」分成互不重疊的垂直區域。名稱與技能色塊之間要保留明顯間距，說明文字不可貼近卡片底邊。若角色圖擠壓文字，優先將圖片縮小約 10% 並調整位置，不縮小已確認的大字，也不以覆蓋名稱換取角色尺寸。

修正角色卡片後，從原尺寸成品裁切整組卡片，另存放大 QA 預覽並逐卡檢查名稱、技能與說明。放大裁切圖只供驗證，不列入學生交付檔。修改即使只影響局部，也要重新輸出正式成品，確認 A4 像素尺寸、300 dpi、色彩模式、文字清晰度及頁面其他區塊未位移；QR Code 區塊若仍存在，也要重新裁切解碼，不能只沿用舊版通過紀錄。

交付前至少完成以下檢查：

1. PNG 像素尺寸、色彩模式與檔名符合規格。
2. 逐張查看 100% 原尺寸，文字、角色、卡片及頁尾沒有裁切、重疊或貼邊。
3. 產生約 390 px 寬的手機縮圖並肉眼檢查，最小文字仍可辨識，資訊順序清楚。
4. 實際解碼成品中的 QR Code，核對完整 URL。
5. 對照實作核對所有中文、數字、單位、機率、時間與安全提醒。
6. 只交付正式 PNG 與必要的可修改來源／設計說明；手機縮圖、裁切圖與驗證依賴留作 QA，不混入學生交付檔。
7. A4 角色卡片逐一卡片確認圖像、名稱、技能色塊與說明分區清楚，沒有遮擋，且說明與卡片底邊保有安全間距。

## 交付訊息

先說結果，給正式網址與實際檔案連結，再說使用方法與未驗證限制。不要把 QA 中間圖、程式碼或 CLI 操作當學生需要的產物。若使用技能影響成果，簡短交代；不宣稱未做過的主觀聽感、實機驗證或密碼遷移。

### 部署到 Cloudflare 與存到 GitHub

正式部署依 [cloudflare-d1-workflow.md](cloudflare-d1-workflow.md)。部署前取得使用者同意；部署後用內建瀏覽器開正式網址實際操作，確認 HTTPS 與互動正常再回報網址。上傳失敗時不要重建另一個 Worker 名稱，先看錯誤訊息核對權限與設定；同一錯誤重複且沒有新證據時，停止盲試並說明限制。

程式碼存到 GitHub 前，確認不含金鑰、帳密檔、`work/`、`.wrangler/`、`node_modules/`、`dist/`；只在使用者要求時 commit 與 push，不初始化或提交父層資料夾。

瀏覽器拒絕某個 URL 協定或權限時，遵守拒絕及其限制，不改走其他工具繞過。檔案開啟失敗、預覽不可用、網站本身失效是不同證據。若使用者自行驗證手機正常並授權公開，可在來源檢查通過後依正常部署流程繼續；不因此聲稱代理已完成該次手機實測。

多人模式另驗隔離登入、並發、重啟及無客戶端連線時的真實截止結算，見 [quizspirit-multiplayer.md](quizspirit-multiplayer.md)。

老師投影與學生雙畫面的事件去重、全班排布、滿版備援及 30／60 人驗證界線，見 [quizspirit-projector-battlefield.md](quizspirit-projector-battlefield.md)。


使用者自行部署時的驗證、測試帳號清理與常見版面陷阱，見 [production-verification.md](production-verification.md)。
